## ১. সিস্টেম ওভারভিউ ও স্পেসিফিকেশন

| কম্পোনেন্ট | প্রযুক্তি / টুলস | ভূমিকা |
| --- | --- | --- |
| **DNS ও ট্রাফিক রাউটিং** | Cloudflare DNS / Load Balancing | গ্লোবাল হেলথ চেক, সাবডোমেইন ফেইলওভার, DDoS সুরক্ষা |
| **লোড ব্যালেন্সিং লেয়ার** | HAProxy + Keepalived (২টি নোড) | ভার্চুয়াল আইপি (VIP), টিসিপি লেভেল ট্রাফিক ডিস্ট্রিবিউশন |
| **MQTT ব্রোকার ক্লাস্টার** | EMQX Cluster (৩টি নোড) | ১ লক্ষ কনকারেন্ট কানেকশন, সেশন ও স্টেট সিঙ্ক |
| **সিকিউরিটি ও এনক্রিপশন** | TLS v1.3 + mTLS / JWT Auth | ডেটা এনক্রিপশন ও ডিভাইস অথেনটিকেশন |
| **অ্যাপ্লিকেশন সার্ভিস** | Node.js Worker Service (PM2 / Docker) | মেসেজ কনজিউম, ডেটা ভ্যালিডেশন, অ্যালার্ট হ্যান্ডলিং |
| **ডেটাবেস লেয়ার** | MongoDB Replica Set (Primary + Secondary + Arbiter) | রিয়েল-টাইম স্টেট সংরক্ষণ ও স্বয়ংক্রিয় ব্যাকআপ |

## ৩. লেয়ার বাই লেয়ার বাস্তবায়ন নির্দেশিকা

### লেয়ার ১: DNS ও মাল্টি-ডোমেইন ফেইলওভার

* **কনফিগারেশন:** ক্লাউডফ্লেয়ারে দুটি সাবডোমেইন তৈরি করুন (যেমন `broker1.example.com` এবং `broker2.example.com`)।
* **হেলথ চেক রুল:** ক্লাউডফ্লেয়ার লোড ব্যালেন্সারে একটি TCP হেলথ চেক রুল সেট করুন যা পোর্ট ৮৮৮৩ বা নোডের পাবলিক আইপি প্রতি ৫-১০ সেকেন্ড পরপর পিং করবে।
* **ডিভাইস-সাইড ব্যাকআপ:** ESP32 ফার্মওয়্যারে দুটি ব্রোকার অ্যান্ডপয়েন্ট ডিফাইন করুন। প্রাইমারি ডোমেইনে ৩ বার কানেকশন ব্যর্থ হলে ডিভাইসটি স্বয়ংক্রিয়ভাবে সেকেন্ডারি ডোমেইনে সুইচ করবে।

### লেয়ার ২: ইনফ্রাস্ট্রাকচার লোড ব্যালেন্সিং (Keepalived + HAProxy)

* **ভার্চুয়াল আইপি:** দুটি সার্ভারের মধ্যে একটি শেয়ার্ড ভার্চুয়াল আইপি (VIP) তৈরি করুন। Keepalived নির্ধারণ করবে কোন সার্ভারটি সক্রিয় (Master) থাকবে।
* **HAProxy মোড:** HAProxy-কে `mode tcp`-তে রান করান যাতে এটি লাইটওয়েট ভাবে MQTT প্যাকেট সরাসরি EMQX ক্লাস্টারে রাউট করে।
* **কানেকশন ডিস্ট্রিবিউশন:** অ্যালগরিদম হিসেবে `leastconn` ব্যবহার করুন, যাতে ১ লক্ষ ডিভাইসের কানেকশন তিনটি ব্রোকারের মধ্যে সুষমভাবে ভাগ হয়ে যায়।

### লেয়ার ৩: ক্লাস্টার্ড ব্রোকার (EMQX)

* **ক্লাস্টারিং:** ৩টি নোড দিয়ে EMQX ক্লাস্টার তৈরি করুন। একটি নোড ডাউন হলে বাকি দুটি নোড কোনো সংযোগ বিঘ্ন ছাড়াই পুরো ট্রাফিক টেনে নেবে।
* **সেশন স্টেট:** শেয়ার্ড সাবস্ক্রিপশন এবং নোড-টু-নোড Mnesia স্টেট সিঙ্ক ব্যবহার করুন।
* **কানেকশন লিমিট টিউনিং:** প্রতিটি সার্ভারের লিনাক্স কার্নেল প্যারামিটারে ফাইল ডেসক্রিপ্টর লিমিট (`ulimit -n 1000000`) এবং `sysctl.conf`-এ সকেট বাফার বাড়িয়ে দিন।

### লেয়ার ৪: সিকিউরিটি ও আইডেন্টিটি

* **TLS/SSL:** পোর্ট ৮৮৮৩-এ TLS v1.3 বাধ্যতামূলক করুন।
* **ডিভাইস ক্রেডেনশিয়াল:** প্রতি ডিভাইসের জন্য ইউনিক ক্লায়েন্ট আইডি, ইউজারনেম এবং হ্যাশড পাসওয়ার্ড (বা mTLS সার্টিফিকেট) ব্যবহার করুন।
* **টপিক অ্যাক্সেস কন্ট্রোল (ACL):** কোনো ডিভাইস যাতে অন্যের টপিকে সাবস্ক্রাইব বা পাবলিশ না করতে পারে সেজন্য EMQX-এর встроен ACL রুলস ব্যবহার করুন:
* পাবলিশ: `device/%c/status`
* সাবস্ক্রাইব: `device/%c/command`



### লেয়ার ৫: ডেটাবেস স্টোরেজ ও টিটিএল পলিসি (MongoDB)

* **রেপ্লিকা সেট:** ৩টি নোডে মঙ্গোডিবি রেপ্লিকা সেট সেটআপ করুন। প্রাইমারি নোড ডাউন হলে ৩-৫ সেকেন্ডের মধ্যে সেকেন্ডারি নোড প্রাইমারিতে রূপান্তরিত হবে।
* **টিটিএল ইনডেক্স (৯০ দিন / ৩ মাস):**
```javascript
db.device_logs.createIndex(
  { "timestamp": 1 },
  { expireAfterSeconds: 7776000 } // ৯০ দিন = ৯০ * ২৪ * ৬০ * ৬০
);

```


* **ব্যাকআপ স্ট্র্যাটেজি:** রেপ্লিকা সেট থাকার পাশাপাশি প্রতিদিন অফ-পিক আওয়ারে (যেমন রাত ৩টায়) `mongodump` চালিয়ে ব্যাকআপ আর্কাইভ করে ক্লাউড স্টোরেজে (S3/Wasabi) আপলোড করার জন্য একটি ক্রন জব সেট করুন।

## ৪. ESP32 ফার্মওয়্যার ফেইলওভার লজিক

```text
Initialize SIM800L / Network
       │
       ▼
Try Connect to Primary Domain (broker1.example.com)
       │
       ├──► [Success] ──► Publish Keep-Alive / Listen Command
       │
       └──► [Fail >= 3 times]
                   │
                   ▼
       Switch to Secondary Domain (broker2.example.com)
                   │
                   ├──► [Success] ──► Normal Operation
                   │
                   └──► [Fail] ──► Hard Reset Modem (Power Cycle) & Retry

```

এই আর্কিটেকচারে কোনো সিঙ্গেল পয়েন্ট অফ ফেইলিওর থাকে না—DNS, লোড ব্যালেন্সার, ব্রোকার কিংবা ডেটাবেসের যেকোনো একটি নোড নষ্ট হলেও সম্পূর্ণ সিস্টেমটি কোনো ডাউনটাইম ছাড়াই কার্যকর থাকবে।
